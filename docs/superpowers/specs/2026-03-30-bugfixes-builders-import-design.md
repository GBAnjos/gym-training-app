# Bug Fixes, Custom Builders & File Import — Design Spec

**Date:** 2026-03-30
**Status:** Approved (rev 2 — post spec review)

## Overview

Four sequential epics that fix exercise display bugs, enhance the existing workout builder, add a custom diet builder, and enable AI-generated plan import via paste or file upload.

---

## Epic 1: Bug Fixes & Plan Preview

### 1.1 — Exercise Images Missing

**Problem:** Exercises like `incline_dumbbell_press`, `barbell_shoulder_press`, `bent_arm_barbell_pullover`, `decline_push_up` show no image.

**Root cause:** `exerciseMediaService.js` already builds a `bundleMap` from exercise IDs, names, and folder names (lines 15-28). However, `findExerciseFolder()` normalizes input by stripping accents, numbers, and trimming — which can mangle certain IDs or names that don't match any entry. Many exercises generated by `advancedPlanGenerator.js` pass the exercise `id` (e.g., `incline_dumbbell_press`) rather than the display `name`, and the bundleMap key normalization doesn't account for underscore-separated IDs.

**Fix:**
- In `exerciseMediaService.js`, extend `buildBundleMap()` to also index by the raw `exercise.id` (without normalization) so that ID-based lookups always resolve
- Add a `getExerciseImageById(id)` convenience function that looks up the bundle entry by `id` and returns `{ startImage, endImage }` from its `gifUrl`
- Update `ExerciseMedia` and `ExerciseMediaCompact` to accept an optional `exerciseId` prop — if provided, try ID-based lookup first, then fall back to existing name-based matching
- This ensures all 512 bundled exercises resolve images automatically

### 1.2 — Underscore Names

**Problem:** Exercise names display with underscores (e.g., `incline_dumbbell_press`).

**Root cause:** `advancedPlanGenerator.js` `formatExercise()` stores `nome: exercise.name` from the bundle. But when exercises are referenced by ID elsewhere (e.g., in TrainingPage's `getExerciseName()` fallback), the raw ID can slip through as a display name.

**Fix:**
- Generator: verify `formatExercise()` always resolves the proper `name` field from the bundle (not the `id`)
- Display safety net: add a `formatExerciseName(name)` utility in a shared location that converts `some_name` → `Some Name` as a last resort (replace underscores with spaces, title-case each word)
- Apply this utility in TrainingPage exercise name resolution and SmartPlanPage preview
- Note: there is no separate `ExerciseCard` component file — the exercise rendering is inline in TrainingPage

### 1.3 — Plan Preview with Swap/Remove

**Already partially built** in SmartPlanPage (`PlanPreview` component with `handleSwapExercise` and `handleRemoveExercise` handlers).

**Verify & fix:**
- Ensure preview screen shows all training days in tabs
- Each exercise shows: image (using ID-based lookup from 1.1), formatted name (from 1.2), sets × reps, RPE
- Swap button: calls `getAlternativeExercise()` to generate an alternative targeting the same muscle group/movement pattern
- Remove button: filters the exercise from that day's array
- "Activate Plan" button only appears on the preview screen (plan is NOT auto-activated on generation)

## Epic 2: Custom Workout Builder (Enhancement)

### Existing State
`WorkoutBuilderPage.jsx` already exists with full functionality: day selection, exercise library search, drag reorder, delete with undo, inline sets/reps editing, and save to `vida_workout_plan`.

### What Needs Enhancement
The existing builder is functional but missing:
1. **Per-day session naming** — currently uses the same workout name for all days. Add a per-day name input (e.g., "Chest + Triceps" for Monday, "Back + Biceps" for Tuesday)
2. **Rest time input** — add optional rest seconds per exercise
3. **Exercise images** — show exercise thumbnails in the builder cards (using `ExerciseMediaCompact`)
4. **Entry point visibility** — ensure "Create My Own" card is prominent on Programs page

### Data Model
Keep the existing shape that `WorkoutBuilderPage` already saves — no breaking changes:

```javascript
{
  name: string,
  splitType: 'custom',           // existing field, keep as-is
  trainingDays: ['Seg', 'Qua', 'Sex'],
  dayActivities: {
    'Seg': {
      type: 'gym',
      session: {
        label: '1',
        name: string,            // per-day session name (enhancement)
        focus: 'custom',
        icon: 'pencil-1'
      },
      exercises: [
        { id, nome, series, reps, restSeconds?, musculos }
      ]
    }
  },
  goals: ['custom'],
  generatedAt: ISO8601           // existing field name, keep as-is
}
```

**Note:** `restSeconds` is optional — TrainingPage already handles exercises with or without it. No `source` field needed; `splitType: 'custom'` and `goals: ['custom']` already distinguish custom plans.

## Epic 3: Custom Diet Builder

### Entry Point
- "Create My Diet" button on Meals page

### Data Model
New localStorage key `vida_custom_diet`:

```javascript
{
  name: string,
  meals: [
    {
      id: string,           // crypto.randomUUID()
      name: string,         // "Breakfast", "Lunch", custom
      time: '07:00',        // optional display time
      foods: [
        {
          id: string,       // crypto.randomUUID()
          name: string,     // "Chicken breast"
          calories: number,
          protein: number,
          carbs: number,
          fat: number,
          quantity: string,  // "200g", "1 cup", freeform
        }
      ]
    }
  ],
  dailyTargets: {
    calories: number | null,
    protein: number | null,
    carbs: number | null,
    fat: number | null
  },
  createdAt: ISO8601
}
```

### Meal Completion Tracking
The existing `meals_completed_YYYY-MM-DD` stores an array of meal indices `[0, 1, 3]`. Custom diets need per-food tracking within meals. New storage key:

`diet_completed_YYYY-MM-DD`:
```javascript
{
  [mealId]: [foodId1, foodId2, ...]  // array of completed food IDs per meal
}
```

The existing `meals_completed_*` pattern remains untouched for the static meal tracker. When a custom diet is active, the Meals page uses `diet_completed_*` instead.

### UX Flow
1. **Set daily targets** (optional) — Calories, protein, carbs, fat inputs. Can skip.
2. **Add meals** — Starts with templates (Breakfast, Lunch, Dinner, Snacks). User can rename, add, remove meals.
3. **Add foods per meal** — Type food name + calories + macros. Simple form, one food at a time.
4. **Save** — Persists to `vida_custom_diet`

### Meals Page Updates
- If `vida_custom_diet` exists, show custom diet view; otherwise show existing static meals
- Toggle/switch to go back to static view or edit custom diet
- Daily total bar: calories consumed vs target (sum checked-off foods)
- Check-off individual foods as eaten (using `diet_completed_YYYY-MM-DD`)
- Edit button opens the builder to modify meals/foods

### Key Decisions
- No food database — user types everything manually (future enhancement: option C)
- Daily targets optional — some users just want a meal schedule
- Bilingual labels (pt-BR / en)
- Static meal plan is preserved; custom diet is an alternative, not a replacement

## Epic 4: File Import (Training + Diet)

### Entry Points
- Programs page: "Import Training" button
- Meals page: "Import Diet" button
- Both open an import flow with the type pre-selected

### UX Flow
1. **Input method** — Two tabs: "Paste Text" (textarea) | "Upload File" (.txt, .md, .csv)
2. **Parse** — Client-side parser extracts structured data
3. **Preview** — Shows parsed result in builder format. Yellow/amber highlights on items parser is unsure about.
4. **Edit** — User can fix, rename, adjust, remove, add items
5. **Import & Activate** — Saves to `vida_workout_plan` or `vida_custom_diet`

### Parser Design

Two parsers in `src/utils/importParser.js`: `parseTrainingText(text)` and `parseDietText(text)`

**Training parser** recognizes:
- Day headers: `## Day 1`, `**Monday**`, `### Push Day`, `Día 1:`, `Segunda`, numbered days
- Exercise lines: `- Bench Press: 4x12`, `1. Squat — 3 sets x 8 reps`, table rows
- Markdown tables: Exercise | Sets | Reps | Rest
- Bullet lists, numbered lists, plain text with delimiters

**Diet parser** recognizes:
- Meal headers: `## Breakfast`, `**Meal 1**`, `### Lunch`, `Café da manhã`
- Food lines: `- Chicken breast 200g (180 cal, 38P/0C/2F)`, `Rice: 150g — 195 kcal`
- Markdown tables: Food | Quantity | Calories | Protein | Carbs | Fat
- Daily totals: `Total: 2200 kcal`, `Daily target: 180g protein`

**Parser strategy:**
1. Detect format (markdown table vs bullet list vs plain text)
2. Split into sections by day/meal headers
3. Extract items per section via regex
4. For training: fuzzy-match exercise names against 512-exercise bundle using existing name normalization from `exerciseMediaService.js` (lowercase, strip accents, token overlap). Match threshold: ≥70% token overlap = confident, 50-70% = uncertain (yellow), <50% = unmatched (kept as plain text)
5. Unmatched exercises kept as plain text with user-editable fields
6. Return structured data + confidence per item (`'high'` | `'medium'` | `'low'`)

**Confidence UI:**
- `high`: normal display (auto-matched exercise or clearly parsed food)
- `medium`: amber/yellow background — parser's best guess, user should verify
- `low`: red outline — parser couldn't parse, shown as raw text for manual editing

**File handling:**
- `.txt`, `.md` — read as plain text via `FileReader`
- `.csv` — split by delimiter, map columns
- No PDF support (avoids 400KB+ pdf.js dependency; users can copy-paste from PDF instead)

**Input limits:**
- Paste: max 50,000 characters (covers any reasonable AI output)
- File upload: max 500KB
- Show friendly error if exceeded

### Key Decisions
- All parsing is client-side (no API calls)
- AI-agnostic: handles ChatGPT, Claude, Gemini, Copilot, etc. output formats
- Bilingual parsing: handles English and Portuguese patterns
- Paid feature flag: `vida_premium` in localStorage (always `true` for now). Only Epic 4 (import) is gated. Epics 2 and 3 (manual builders) are free.
- No PDF support to keep bundle size small — can be added later if needed
